# DATA MODEL

## Назначение

Документ описывает логическую модель данных проекта и назначение основных таблиц SQLite.  
SQLite является единственным источником истины для рабочих данных проекта.  
Точная техническая структура базы данных определяется файлом:

```
database/schema.sql
```

---

## Основные принципы

-  исходные данные импортируются в SQLite; 
-  производные данные формируются программно; 
-  производные данные не редактируются вручную; 
-  территориальные корректировки должны быть воспроизводимыми; 
-  учитываемая площадь суши не должна учитываться более одного раза; 
-  алгоритмы сопоставления работают с подготовленными данными; 
-  результаты экспериментов не являются частью исходных данных. 

---

## Слои данных

Логический поток данных:

```
Исходные данные
      ↓
Raw-таблицы
      ↓
Территориальные корректировки
      ↓
Подготовленные данные
      ↓
Candidate sets
      ↓
Assignments
      ↓
Analysis / Reports
```

---

## Основные таблицы

### subjects

Содержит субъекты Российской Федерации, участвующие в задаче сопоставления.

Основные поля:

- `id` 
- `name` 
- `type` 
- `federal_district` 
- `area_km2` 

`area_km2` используется как целевая площадь субъекта.

---

### countries_raw

Содержит исходные данные о странах, импортированные из внешнего источника.

Основные поля:

- `id` 
- `name` 
- `iso_alpha2` 
- `iso_alpha3` 
- `continent` 
- `area_km2` 

Таблица представляет исходные данные до применения проектных правил нормализации.

---

### territory_adjustments

Содержит территориальные корректировки, применяемые к исходным данным.

Корректировка описывает:

-  территорию; 
-  площадь; 
-  государство-источник; 
-  государство-получатель; 
-  комментарий и основание. 

Таблица используется для воспроизводимого формирования подготовленных площадей.

---

### countries_final

Содержит подготовленный набор государств-кандидатов, используемый алгоритмами сопоставления.

Основные поля:

- `id` 
- `name` 
- `iso_alpha2` 
- `iso_alpha3` 
- `continent` 
- `area_km2` 

`area_km2` представляет площадь после применения территориальных корректировок и других правил нормализации.

Именно `countries_final` является входным набором государств для генерации кандидатов.

---

### candidate_sets

Содержит наборы кандидатов, сформированные для субъектов РФ.

Каждый набор относится к конкретному субъекту и представляет подготовленные варианты сопоставления.

---

### candidate_items

Содержит элементы наборов кандидатов и связывает их с соответствующими государствами.

Основное назначение таблицы — хранение состава и характеристик конкретных вариантов кандидатов.

---

### assignments

Содержит итоговые назначения, сформированные алгоритмом сопоставления.

Каждое назначение относится к одному субъекту РФ.

---

### assignment_items

Связывает итоговое назначение с государствами, входящими в соответствующую комбинацию.

Одно назначение может содержать несколько государств.

---

## Связи между таблицами

Основной поток генерации кандидатов:

```
subjects
   │
   └── candidate_sets
           │
           └── candidate_items
                    │
                    └── countries_final
```

Основной поток формирования назначений:

```
subjects
   │
   └── assignments
           │
           └── assignment_items
                    │
                    └── countries_final
```

Поток подготовки площадей:

```
countries_raw
      │
      ├── territory_adjustments
      │
      ├── правила нормализации
      │
      └── ручные добавления
                │
                ↓
        countries_final
```

---

## Производные данные

`countries_final` является производным набором данных.

Он формируется на основе:

```
countries_raw
      +
territory_adjustments
      +
правила нормализации
      +
ручные добавления
      ↓
countries_final
```

Подготовленные значения не должны редактироваться вручную.

---

## Candidate generation

Генератор кандидатов использует:

```
subjects
countries_final
```

и формирует:

```
candidate_sets
candidate_items
```

Этот слой отвечает за подготовку допустимых вариантов сопоставления и не определяет итоговое распределение субъектов.

---

## Assignment

Слой назначения использует подготовленные candidate sets и формирует:

```
assignments
assignment_items
```

Этот слой отвечает непосредственно за выбор итоговых комбинаций.

Конкретный алгоритм сопоставления определяется отдельно и не является частью логической модели данных.

---

## Analysis

Модуль анализа использует данные из:

```
assignments
assignment_items
countries_final
subjects
```

и формирует производные показатели качества распределения.

Результаты анализа не изменяют основную модель данных.

---

## Эксперименты и экспорт

Эксперименты выполняются поверх данных SQLite и не являются отдельным слоем исходных данных.

Текстовые результаты хранятся в:

```
experiments/
```

Экспортируемые результаты хранятся в:

```
exports/experiments/
```

Точная структура таблиц, столбцов, ограничений и связей определяется:

```

```

При расхождении между логическим описанием и технической схемой приоритет имеет `database/schema.sql`.
