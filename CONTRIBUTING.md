# CONTRIBUTING

## Основные принципы разработки

1. **Один источник истины для данных — SQLite.**
2. **Все изменения проекта проходят через Git.**
3. **Каждый законченный логический этап оформляется отдельным коммитом.**
4. **Номер версии не обязан соответствовать одному коммиту.** Несколько коммитов могут относиться к одной версии.
5. **Завершённые версии отмечаются Git tag** в формате `vMAJOR.MINOR.PATCH`.
6. **Архитектурные изменения допускаются только при наличии серьёзных оснований** и должны быть отражены в `DECISIONS.md`.
7. **Новые модули должны создаваться максимально близкими к предполагаемой финальной архитектуре.**
8. **Производные данные не редактируются вручную.** Они должны воспроизводиться из исходных данных и правил обработки.
9. **Эксперименты должны быть воспроизводимыми.** Конфигурация, ограничения и порядок обработки должны быть явно зафиксированы.
10. **Результаты экспериментов не должны смешиваться с исходными данными.** Отчёты и экспортируемые результаты хранятся в соответствующих каталогах.
11. **Изменения алгоритмов сопровождаются экспериментальной проверкой.** Результаты фиксируются в `experiments/EXPERIMENTS.md`.
12. **Проектная документация поддерживается в актуальном состоянии.** Существенные изменения отражаются в соответствующих документах.
13. **Код должен быть воспроизводимым и документированным.**
14. **Устаревшие модули и файлы-заглушки удаляются**, если их функциональность перенесена в актуальную архитектуру.

## Работа с версиями

Проект использует Semantic Versioning:

```text
MAJOR.MINOR.PATCH

```

До версии `1.0.0`:

- `MINOR` обозначает новый существенный этап разработки;
- `PATCH` обозначает исправление или небольшое изменение внутри текущего этапа;
- `MAJOR` до `1.0.0` не используется для обычного развития проекта.

Завершённые версии фиксируются Git tag, например:

```text
v0.2.0
v0.2.1
v0.2.2
v0.3.0

```

## Именование коммитов

Сообщения коммитов должны кратко описывать изменение.

Рекомендуемый формат:

```text
type(scope): description

```

Примеры:

```text
feat(algorithm): add greedy assignment
feat(experiments): add median error statistics
fix(data): correct territory aggregation
docs: update project state
refactor(database): simplify database initialization

```

Номер версии **не требуется** указывать в сообщении каждого коммита. Версия определяется совокупностью изменений и фиксируется Git tag.

## Документация

Документация разделяется по назначению:

- `README.md` — общее описание проекта и точка входа;
- `PROJECT_STATE.md` — текущее состояние проекта;
- `ROADMAP.md` — этапы развития проекта;
- `TODO.md` — незавершённые задачи;
- `SPECIFICATION.md` — требования к задаче;
- `DATA_MODEL.md` — логическая модель данных;
- `DECISIONS.md` — принятые архитектурные и методологические решения;
- `HYPOTHESES.md` — проверяемые гипотезы;
- `EXPERIMENTS.md` — результаты экспериментов;
- `CHANGELOG.md` — история значимых изменений и версий.
